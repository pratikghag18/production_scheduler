## Reproduction

On a fresh stack built the way CI and the tester harness build one — `supabase db reset`
(migrations + `seed.sql` + `dev_demo.sql`, per `config.toml` `sql_paths`), which is exactly what
`scripts/ci-e2e.sh` line 65 and `npm run tester -- --e2e` do — read Plant A's operator roster:

```
docker exec supabase_db_production_scheduler psql -U postgres -d postgres \
  -tc "select display_name from operators order by 1 limit 8;"
```

or run the two e2e specs that name the real people:

```
npx playwright test e2e/linePeople.spec.ts e2e/viewerBoard.spec.ts --project=chromium --workers=1
```

Nothing in any automated path applies `scripts/demo/rename-plant-a-operators.sql`. Confirmed:

```
grep -rn "rename-plant-a" scripts/ e2e/ playwright.config.ts package.json supabase/
```

returns only comments (the script's own header, and explanatory comments in `linePeople.spec.ts`
and `viewerBoard.spec.ts`) — no `ci-e2e.sh`, no `tester-run.mjs`, no playwright `globalSetup`
(the config has none; `webServer` only runs `npm run dev`), no `config.toml` entry.

## Expected

R-423's claim: *"The six demo operators homed on Plant A's cells (employee refs EMP-1001 to
EMP-1006) are Sam Patel, Maria Lopez, John Kim, Priya Shah, Tom Baker and Lena Novak, renamed by
`scripts/demo/rename-plant-a-operators.sql` ... ; the two e2e specs that name them name the new
ones."* R-423 is recorded `status: covered`, verified by `e2e/linePeople.spec.ts` and
`e2e/voiceBar.spec.ts`. So on the stack those specs run against, the six operators must carry their
real names and the specs must pass.

## Actual

The roster is generic on every fresh stack — the rename never runs:

```
 Contoso Operator A
 Contoso Operator B
 Operator A1
 Operator A2
 Operator A3
 Operator A4
 Operator A5
 Operator A6
```

and none of the six real names exist:

```
select display_name from operators where display_name in
  ('Sam Patel','Maria Lopez','John Kim','Priya Shah','Tom Baker','Lena Novak');
-- (0 rows)
```

so the specs verifying R-423 fail. `e2e/linePeople.spec.ts:125`:

```
Error: expect(received).toEqual(expected) // deep equality
- Expected  - 6
+ Received  + 6
  Array [
-   "John Kim",
-   "Lena Novak",
-   "Maria Lopez",
-   "Priya Shah",
-   "Sam Patel",
-   "Tom Baker",
+   "Operator A1",
+   "Operator A2",
+   "Operator A3",
    ...
```

`e2e/viewerBoard.spec.ts:71` never finds an operator chip:

```
Error: expect(locator).toBeVisible() failed
Locator: getByRole('button', { name: /(?:Operator A\d|Sam Patel|Maria Lopez|John Kim|Priya Shah|Tom Baker|Lena Novak) on /i }).first()
Error: element(s) not found
```

Full serial run (`npx playwright test --workers=1`): **35 passed, 10 failed**. The four board-data
specs run in isolation, serially, on a quiet machine still fail (**6 failed, 2 passed**) — so this
is not contention flakiness. (`typedWalk`/`voiceBar` additionally need the served model service;
`touch` T2/T3/T5 are a separate gesture-flakiness question, not this defect.)

This is invisible to `confirmed: true` sessions because those run `npm run test` (unit) only —
e2e is never in that count, so these six specs have been red on every automated run since S60
shipped without moving the confirmed number.

## Lead

**A lead, not a fact — the developer decides.** R-423 deliberately keeps the rename OUT of the seed
files ("no seed file creates them"), so the fix is probably not `config.toml` `sql_paths`. The
likely home is a post-reset step in the automated harness: apply
`scripts/demo/rename-plant-a-operators.sql` through the db container right after `supabase db reset`
in `scripts/ci-e2e.sh`, and in whatever `tester-run.mjs` uses to build its `--e2e` stack, and/or a
playwright `globalSetup`. The pin (`src/test/defects/DEF-0034.test.ts`) asserts the contradiction
statically — the rename script exists and names the six, but no automated entry point references it
— so it goes green the moment the rename is wired into one. Worth deciding at the same time whether
R-423's manual-script design is what you still want, given it means every fresh demo shows
"Operator A1" until someone runs a script by hand.
