## Reproduction

At tip `03700f1`, in `src/features/board/hooks/useDragGesture.ts:1021`, widen the guard that skips
the keep-or-scale prompt when the scaled figure rounds back to the typed one:

```
-        if (a.targetQty !== null && scaled !== null && scaled !== a.targetQty) {
+        if (a.targetQty !== null && scaled !== null) {
```

Then:

```
npx vitest run src/test/dragGesture.test.ts src/test/standardTarget.test.ts src/test/interaction.test.ts
```

## Expected

R-031's own claim: *"a scaled figure that rounds back to the typed one asks nothing."* A resize
that changes a block's length but produces the identical scaled figure (after `roundTarget`'s own
rounding) should commit without a prompt, the same as the "same length" case R-031e/T18e already
cover.

## Actual

```
 Test Files  3 passed (3)
      Tests  97 passed (97)
```

All 97 cases across the three files this feature touches stay green with the guard removed --
meaning a resize that SHOULD commit silently would instead open the "Keep or scale?" prompt
unnecessarily, and nothing under `src/test/` would notice. Mutation reverted before writing this
up (`git diff` empty afterward).

This is a real, reachable gap, not a theoretical one: `oldMinutes`/`newMinutes` differing by a
non-multiple of the 30-minute snap grid is exactly what Alt-drag produces (`snapMinute`'s own
branch: "Holding Alt disables snapping entirely and gives whole minutes"), and rounding collisions
are ordinary arithmetic, not edge cases -- confirmed with a positive-control case run against the
UNMUTATED, committed code: an Alt-drag that shortens a 1000-minute block carrying a target of 10 by
exactly one minute (`scaledTarget(10, 1000, 999)` = 10, the same figure) correctly opens no prompt
today. The suite has no case anywhere that exercises this path either way -- not the guard's
presence, and not its absence.

## Lead

A suspicion, not a fact, on where the gap in the suite specifically is. R-031a-g all drive a
30-minute-snapped drag (no Alt), so `scaled` never lands exactly on `a.targetQty` in any of them
except via the already-covered "same length" branch (`scaledTarget`'s own early return, T18e). A
hook-level case that Alt-drags a block by an amount whose rounded scale exactly equals the typed
figure -- and asserts `result.current.popover` stays `null` -- would close this without touching
product code; the pure-function half (`scaledTarget` returning the unchanged quantity for a genuine
length change) could also be pinned directly in `standardTarget.test.ts` beside T18e, which only
covers the zero-length-change case today.
