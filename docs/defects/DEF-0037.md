## Reproduction

On the tester's stack (fresh `tester-stack.mjs up`, demo seed), as the company admin
(`dana@example.test` / `devpassword`) record any absence for **John Kim** (a Plant A person homed
off Line 1). Then sign in as **Ana** (`ana@example.test`, Line 1 supervisor):

1. `/admin` → **Absences**. John Kim's row is listed with a **Remove** button. Press it.
2. `/admin` → **Operators** → John Kim. His block reads "You cannot record an absence for this
   person from here." and, in the same block, lists the absence with a **Remove** button.

Server half, scripted (the tester's scratch script, run against the stack):
`absence_recordable_people()` as Ana, then `set_absence` as the admin for someone outside that set,
then as Ana a SELECT of that absence and `remove_absence` on it, then a read-back.

Pins: `npx vitest run src/test/defects/DEF-0037.test.tsx src/test/defects/DEF-0037-panel.test.tsx`
(the first is the Operators block, the second the Absences tab).

## Expected

R-360: the person's absences are "read, recorded and removed" on their record "gated by the same
server predicate" the Absences tab uses; R-357: an absence is recorded by "a supervisor or admin of
the person's place". CLAUDE.md §4 / R-431's rule for screens: whatever a client offers is decided by
the test the server runs. `remove_absence` (0066) gates on `app_can_edit_node(coalesce(home, site))`
-- the same expression `absence_recordable_people()` (0084) answers as a set, which both screens
already fetch. A person outside that set should have no Remove to press.

## Lead

**A suspicion, not a fact.** DEF-0035's second fix gated the record half on the server's set and
left the remove half as it was (`OperatorAbsences.tsx` ~l.188 and `AbsencesPanel.tsx` ~l.273 render
Remove for every readable row; the old block did the same before the refactor, so this predates the
range but is newly glaring beside the new sentence). Both screens already hold the set
(`recordableQuery`, `recordableIds`); a row whose `operatorId` is not in it could render no Remove,
keeping Sam's. `88_absences_test.sql` AB5 already holds remove to the same gate as record, so the
set answers both. The "this cell" wording is `describeSchedulerError`'s NotPermitted case.
