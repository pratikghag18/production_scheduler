## Reproduction

On the machine, with any free port and a scratch folder:

```
node scripts/voice/clips/record.mjs --port 18097 --out <scratch>/rec
netstat -ano | findstr :18097
curl http://<this machine's LAN address>:18097/manifest.json
```

From a second machine on the same network the same `curl`, and `curl .../clip/1 -o x.wav` or a POST
to `/clip/1`, reach it the same way (routes in `record.mjs`: GET `/clip/<n>`, GET
`/manifest.json`, POST `/clip/<n>`, no authentication).

## Expected

R-460 (added by the tester this session, `stated_by: agent`): a tool the project runs on this
machine listens on this machine only. The page itself says so: it prints
`recording page: http://127.0.0.1:<port>/`, and the Whisper container `serve.mjs` starts is
published on `127.0.0.1:` deliberately.

## Actual

```
  TCP    0.0.0.0:18097          0.0.0.0:0              LISTENING       30620
  TCP    [::]:18097             [::]:0                 LISTENING       30620
GET manifest over LAN-facing interface: 200
   IPv4 Address. . . . . . . . . . . : 192.168.1.180
recording page: http://127.0.0.1:18097/
```

(Found by a tester lane and re-run by the tester; the server was stopped afterwards.) The clips are
the maintainer's own voice reading the walk's sentences; a POST replaces a clip silently, and every
later `voice:clips:score` table is computed from whatever is on disk.

## Lead

**A suspicion, not a fact.** `record.mjs:443` calls `server.listen(args.port, cb)` with no host, and
Node binds every interface when the host is omitted; `server.listen(args.port, "127.0.0.1", cb)`
matches what the banner prints. Read from source only, not run: `serve.mjs` ~l.295 publishes the
llama.cpp model container as `-p ${HOST_PORT}:${CONTAINER_PORT}`, which Docker binds on all
interfaces, while the Whisper container two blocks above uses `127.0.0.1:`; the asymmetry has no
comment defending it. Also read, not a finding on its own: the Vite `/__clip` endpoint reads the
whole request body with no size cap (`clipServer.ts` `readBody`), harmless while Vite binds loopback
(it does -- no `server.host` anywhere) but worth a cap if that ever changes.
