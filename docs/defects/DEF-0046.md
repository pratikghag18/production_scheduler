## Reproduction

Tester's stack, demo seed, any person who can place (Ana or the admin), a cell with a block today
(Cell 1: Sam Patel 14:00-22:00). Open the bar and type **"extend everyone on Cell 1 by 30
minutes"**, Enter. Watch the browser console.

Second route, with the served model on (`npm run voice:serve`, dev server with
`VITE_VOICE_URL=/voice`): type "sorry, this will take a few extra minutes, go ahead without me".
The model reads it as a move of everyone, end +30 minutes; the bar asks "I heard ... Did you mean:
extend "everyone" by 30 minutes?" with that as one button. Press it (or type yes).

Pin: `npx vitest run src/test/defects/DEF-0046.test.ts` -- the model's exact reading, expanded and
resolved step by step the way `runCommand` does.

## Expected

R-407: "move everyone" reads everyone as the reserved word and expands to one command per block --
the extend reaches every block on the cell, or the bar asks. R-431: a button the bar offers is one
the bar can carry out. R-434: every turn is a trace entry.

The pin, which also shows why:

The parser gives the typed sentence the same shape the model gave the misheard one:
`{"intent":"move","operator":"everyone","place":["Cell 4"],...,"adjust":{"edge":"end","by":30}}`.

## Lead

**A suspicion, not a fact.** Expanding a move of everyone builds one move per block with
`existing` filled but drops the sentence's `adjust` (`adjust: null`), so each step is a move with no
new cell, no span, no shift and no adjust, and `resolveMoveCommand` reads `.start` of the null
span. Either the expansion carries `adjust` into each step, or a step with nothing to change is a
question, never a throw. Separately, a throw inside a candidate press should not leave the thread
frozen: R-434 wants the turn recorded even when it fails. The live model producing a sweeping
reading from an unrelated sentence is DEF-0041's concern; this defect is the crash.
