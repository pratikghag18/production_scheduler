## Reproduction

`npx vitest run src/test/defects/DEF-0041.test.ts`

The pin calls `groundReading` -- the check the bar runs on every model reading
(`CommandBar.tsx` ~l.2455) -- with the bar's own verb lists (`GROUNDING_VERBS`, `CommandBar.tsx`
~l.238, copied field for field) on a heard sentence that asks for nothing, and the reading F-215
was about: an unassign of everyone with no day, i.e. clear the whole board.

## Expected

F-215's fix (2b9828a), under R-431 and R-435: "an unassign with no removal word ... is refused
outright ('Did not run: nothing in ... says clear, remove or unassign. Say it again.')" -- the
sweeping reading must never reach a "Do all" button unless the person actually said a removal.

## Actual

```
× a garbage transcript that happens to contain the ordinary word 'take' grounds a sweeping clear-everyone
AssertionError: expected { ok: true } to deeply equal { ok: false, reason: 'sweeping', …(1) }
× 'the shipment is out for delivery today' grounds the same sweeping clear-everyone via 'out'
AssertionError: expected { ok: true } to deeply equal { ok: false, reason: 'sweeping', …(1) }
```

Heard: "sorry, this will take a few extra minutes, go ahead without me" and "the shipment is out
for delivery today, nothing else to say". Both ground a clear of everyone. Found by a tester lane;
re-run red by the tester in its own tree.

## Lead

**A suspicion, not a fact.** `groundOne` asks whether ANY word of the intent's list appears
ANYWHERE in the heard text (`hasAnyWord`). The unassign list is `UNASSIGN_VERBS` plus
`ABSENCE_WORDS`, and it holds everyday words: "take" (added at R-405 for "take Sam to Cell 2"),
"out", "off", "away". A word the sentence uses as ordinary English satisfies the guard. The sweeping
case (everyone, no named person or place) is the one that matters; it may want a stricter test --
the removal word adjacent to a person, a place or "everyone", or at the head of the sentence --
while the narrow cases keep today's rule. Not checked: whether the served model actually produces
such a reading for these sentences today; F-215 shows it produced one for "EF76.".

## Tester note -- 28 Sept, second pass: the served model does produce sweeping readings

With the default model file served (`scheduler-voice.gguf` via `npm run voice:serve`, Whisper small.en), the app's own `readSentence`
read "sorry, this will take a few extra minutes, go ahead without me" as
`{"intent":"move","operator":"everyone",...,"adjust":{"edge":"end","by":30}}` in 9.2 s. Grounding
answered `no_intent_word` for that move, so the bar asked it as a one-button question rather than
refusing it; only a sweeping UNASSIGN is refused outright. Pressing that button crashes (DEF-0046).
The unassign case this defect pins was not reproduced from the model with these sentences.

## Tester note -- 30 Sept, re-verification (session 195t)

Both pin cases green at 953c900; the rule refuses the defect's two sentences and the reviewer's.
The tester then tried seventeen more ordinary sentences against the new rule. It refuses "who cleared
everyone", "wipe the board clean" and "everyone off the clock at five", and still grounds a clear of
the whole board for ten others -- a negation ("do not clear the board"), a question ("is everyone
off today") and an idiom ("I will clear it with everyone"). That is a narrower hole than this
defect's and is filed on its own as DEF-0056, with a pin.
