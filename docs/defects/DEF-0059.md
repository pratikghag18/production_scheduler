## Reproduction

With a stack up (`node scripts/tester-stack.mjs up`; the developer's `npx supabase start` publishes
the same way on its own ports):

```
docker ps --format "{{.Names}}\t{{.Ports}}"
netstat -ano | findstr "LISTENING" | findstr ":5442"
curl http://<this machine's LAN address>:54421/rest/v1/
```

## Expected

R-460 (a standard since 28 Sept): "Every server a project script starts for local work ... binds the
loopback interface only, so a person on the same network cannot read or overwrite what it holds."
The standard's second duty (CLAUDE.md §7): the session that sets it greps for what already violates
it. Session 194 fixed the recording page and the model container; the largest server the project
starts was not on the list.

## Actual

```
supabase_db_production_scheduler_tester       0.0.0.0:54422->5432/tcp, [::]:54422->5432/tcp
supabase_studio_production_scheduler_tester   0.0.0.0:54423->3000/tcp, [::]:54423->3000/tcp
supabase_inbucket_production_scheduler_tester 0.0.0.0:54424->8025/tcp, [::]:54424->8025/tcp
supabase_kong_production_scheduler_tester     0.0.0.0:54421->8000/tcp, [::]:54421->8000/tcp

  TCP    0.0.0.0:54421          0.0.0.0:0              LISTENING
  TCP    0.0.0.0:54422          0.0.0.0:0              LISTENING
  TCP    0.0.0.0:54423          0.0.0.0:0              LISTENING
  TCP    0.0.0.0:54424          0.0.0.0:0              LISTENING

API over LAN address (kong 54421): 200
Studio over LAN address (54423): 307
Mail catcher over LAN address (54424): 200
Postgres over LAN address (54422): TCP connect OK
dev server over LAN address (5174): 000 (refused)
```

The requests were made from this machine to its own LAN address (192.168.1.180), as DEF-0039's
were; a second machine was not used, and a firewall rule could still stand between. The database
accepts `postgres` / `postgres` (the connection string `tester-stack.mjs` prints), Studio needs no
sign-in, and the mail catcher holds every invite and password-reset link. The Vite dev server is
loopback-only, as R-460's note says. What the stack holds is the demo world, not a plant's data.

## Lead

**A suspicion, not a fact.** The Supabase CLI publishes its containers on every interface and, as
far as the tester could see, `config.toml` has no bind-address setting; if so the choices are a
firewall rule scoped to those ports, Docker's own default bind address (`"ip": "127.0.0.1"` in the
daemon settings, which the maintainer would set, not a script), or writing the limit into R-460 as a
named exception. The maintainer decides which; the defect is that the standard says "every server"
and this one was not looked at.
