## Reproduction

Tester's stack, demo seed; Sam Patel has two blocks tomorrow (Cell 1 09:00-11:00 and 14:00-22:00).
Sign in as **Ana**, open the bar, type **"Sam Patel is off tomorrow"** (the same for "Maria Lopez
is off tomorrow"). The maintainer's own spoken walk of 24 Sept says exactly this sentence ("Maria
Lopez is off today", two clips in `data/voice/trace/clips`).

Pin: `npx vitest run src/test/defects/DEF-0048.test.ts`.

## Expected

R-409: "'Sam is off today' ... the resolver expands it into one removal per block per day, in board
order, with existing filled in" -- "their blocks go with one yes". R-357: an absence is recorded in
the app; R-409's own words "No absence record is written -- the app has none" predate R-357 (7 Sept)
and are no longer true of the app.

## Actual

As Ana:

```
SAY  Sam Patel is off tomorrow
BAR  Sam Patel has 2 blocks Tue Sep 29. Remove which? Remove Cell 1 · Housing A 09:00–11:00 Remove Cell 1 · Line 1 Subassembly A 14:00–22:00
```

There is no button for both. The parser gives the absence the exact shape of a single removal:

```
Sam Patel is off tomorrow -> {"ok":true,"command":{"intent":"unassign","operator":"Sam Patel","place":[],"day":{"kind":"tomorrow"},"span":null,"existing":null,"shift":null,"until":null}}
```

The pin:

```
× 'Priya Shah is off today' with two blocks today expands to two removals, not a which-block question
AssertionError: expected [ { intent: 'unassign', …(7) } ] to have a length of 2 but got 1
```

`commandResolve.test.ts` AB1-AB3 cover only the "until" form; the one-day form has no case.

## Lead

**A suspicion, not a fact.** Only `until` marks a removal as an absence today, so "off tomorrow"
is indistinguishable from "remove Sam tomorrow". The absence grammar could set a flag the resolver
reads to take every block on the day. Whether the bar should also write an absence record through
`set_absence` now that the app has them (R-357) is the maintainer's call; R-409's sentence saying
the app has none is stale either way.
