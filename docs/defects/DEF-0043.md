## Reproduction

1. Any clear of a job with a planned headcount of 1 (every seeded job): "clear Cell 4 in Line 2
   2026-10-12" as in DEF-0040, or the typed walk's first sentence.
2. Press Do all on that lot and read the Done line.
3. "clear Sam Patel this week" when Sam has no blocks that week.

Pins: `npx vitest run src/test/defects/DEF-0043.test.ts src/test/defects/DEF-0043-headcount.test.ts`.

## Expected

R-459: "Everything the bar prints in the thread is a complete plain sentence in the register of a
shift supervisor ... days as 'today', 'tomorrow', 'Mon 28 Sep'." One person is "1 person"; the Done
line names the day the way its own question did; a refusal about Sam names Sam.

## Actual

```
Ready to do 2 things: ... 2. The Housing A job is off Cell 4 Mon Oct 12; that was 10 pm to 6 am, for 1 people. ...
Done, 2 things. Written: ...; The Housing A job is off Cell 4 2026-10-12; that was 10 pm to 6 am, for 1 people.
```

```
× the run removal's readout says 'for 1 person', not 'for 1 people'
AssertionError: expected 'The Housing A job is off Cell 4 2026-...' to contain 'for 1 person'
× 'clear Sam Patel this week' with no blocks at all names Sam, not 'The board'
AssertionError: expected 'The board has nobody on it this week.' to contain 'Sam Patel'
```

## Lead

**A suspicion, not a fact.** `resolve.ts` writes "people" unconditionally at three sites (~2526
"For N people.", ~3138 "now takes N people", ~3818 ", for N people"). The run removal's readout is
built with `iso` (the raw `YYYY-MM-DD`, ~3860) where the question shows the spoken day -- the
question and the Done line seem to take different strings. `expandRepeatUnassign`'s empty case
(~5210) picks "The board" from `command.place.length` without asking whether the removal named a
person.
