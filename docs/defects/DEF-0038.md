## Reproduction

Fresh demo seed (Plant A resolves to America/Chicago, R-450). Sign in as **Ana**
(`ana@example.test`), open the board, focus Cell 1's track ("Cell 1 track -- press Enter to
create") and press Enter. Read the shift chips and the time line under "Planned headcount".

The same facts are printed by every `e2e/roleWalk.spec.ts` run (`chips=[...]` in its WALK lines).
Pin: `npx vitest run src/test/defects/DEF-0038.test.ts`.

## Expected

R-426 (a standard): "every day and hour the app shows, reads or writes is in" the plant's zone.
R-450: Shift 1 at 06:00 is 06:00 in Chicago. The chips should read Shift 1 06:00-14:00, Shift 2
14:00-22:00, Shift 3 22:00-06:00, and the new block's line the Chicago day and hours -- the same
clock the board's axis behind it uses.

## Actual

Playwright, as Ana, tester's stack, browser zone set to America/Chicago:

```
TRACK label: Cell 1 track — press Enter to create
CREATE POP-UP chips: [ 'Shift 1 11:00–19:00', 'Shift 2 19:00–03:00', 'Shift 3 03:00–11:00' ]
CREATE POP-UP text head: New Product run Direct assignment Shift 1 11:00–19:00 Shift 2 19:00–03:00 Shift 3 03:00–11:00 Product Housing A ... Planned headcount Mon Sep 28 11:00 – 19:00 Cancel Create
```

The screenshot shows the board's axis at 08:00, 09:00, 10:00 ... beside the pop-up's 11:00-19:00.
The roleWalk run in the same session printed the same for every supervisor
(`WALK Ana ... chips=[Shift 1 11:00–19:00 | Shift 2 19:00–03:00 | Shift 3 03:00–11:00]`, and Marco
on Plant B). The pin:

```
× BoardPage mounts CreatePopover with the plant's zone, as it does every other pop-up
AssertionError: BoardPage's <CreatePopover> is mounted without zone=, so its chips and times read UTC: expected false to be true
```

Writes are not affected (the pop-up saves minute offsets from the window start); the labels are,
including the day in `formatFull`, so a 22:00 Chicago start reads as the next day's 03:00.

## Lead

**A suspicion, not a fact.** `CreatePopover` declares `zone?: string` and passes it to
`formatClock`/`formatFull`/`leaveLine`, whose default is `BOARD_ZONE = "UTC"`
(`src/features/board/lib/time.ts:24`). `BoardPage.tsx` ~l.1460 mounts `<CreatePopover>` without
`zone`; the other pop-ups it mounts pass `zone={zone}` (~l.1520, 1609). Never passed, as far back as
the history goes -- invisible until R-450 moved the demo off UTC on 22 Sept. `dateSeam.test.ts`
cannot see it (it hunts machine-zone getters). Making the prop required, here and on any sibling
that defaults to `BOARD_ZONE`, would let `tsc` find the next one.
