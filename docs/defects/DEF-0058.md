## Reproduction

A checkout made by Git for Windows with its default `core.autocrlf=true` (the tester's worktree is
one; any file Git writes out arrives with CRLF -- `git ls-files --eol scripts/run-sql-test.sh` reads
`i/lf w/crlf`). After `git merge --ff-only Development`:

```
node scripts/tester-run.mjs --sql
npx vitest run src/test/voiceClipsScorer.test.ts
```

## Expected

R-366: "The SQL runner (`scripts/run-sql-test.sh`) and `db:types` reach whichever stack the run
names" -- the tester's run works from the tester's worktree. A test added to the suite passes on a
fresh checkout of the machine the project is built on.

## Actual

Every SQL step of the run, 66 of 66:

```
scripts/run-sql-test.sh: line 40: set: pipefail: invalid option name
scripts/run-sql-test.sh: line 55: syntax error near unexpected token `$'{\r''
scripts/run-sql-test.sh: line 55: `build() {'
exit 2
```

The scorer's tests (new in session 194):

```
 FAIL  src/test/voiceClipsScorer.test.ts > VCS: score.mjs, the recorded-set path (--clips) > one scored, one missing, one failed clip ...
SyntaxError: Invalid or unexpected token
 Test Files  1 failed (1)
      Tests  4 failed (4)
```

Proved to be the line endings and nothing else: with `scripts/voice/clips/score.mjs` rewritten to LF
in place (`git status` shows no change, the index is LF) the same file reads `Tests 4 passed (4)`;
put back, `4 failed (4)`. The SQL suite runs when bash is told to ignore carriage returns (`bash -o
igncr scripts/run-sql-test.sh ...`), which is how this session measured it: 65 tally lines, 906
passed, 0 failed.

The developer's own checkout does not show either, because the files there were written by the
editor with LF and never checked out again; they will the first time Git rewrites them (a branch
switch, a stash, a fresh clone).

## Lead

**A suspicion, not a fact.** There is no `.gitattributes`. One line, `* text=auto eol=lf` (or at
least `*.sh text eol=lf` and `*.mjs text eol=lf`), makes every checkout hold what CI holds, and would
also end the standing "format:check lists every file" artifact in the tester's worktree (507 files
this run) that F-116's pre-commit hook was built to work around. Why the scorer's test breaks on
CRLF was not chased: the script opens with `#!/usr/bin/env node` and the test imports it through
vitest with a `?run=` query; the shebang line's `\r` is the likely token.

## Developer note -- 30 Sept, session 195

`.gitattributes`: `* text=auto eol=lf` (and `*.png binary`). Proved with a Windows-style checkout
(`git -c core.autocrlf=true checkout-index --prefix=<scratch>/`) of the runner and the scorer: 113
and 746 carriage returns before, 0 after. The index held LF everywhere already, so no file changed.
The tester's worktree, checked out before this, still holds CRLF copies until Git rewrites them:
after merging, run `git rm -rq --cached .` then `git reset --hard` there once (or `git add
--renormalize .`), and `format:check` should stop listing every file.
