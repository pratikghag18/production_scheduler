## Reproduction

In the running app at `http://localhost:5174` (committed tip `b32ead3`):

1. Sign in as **Admin (company — all three plants)**.
2. Go to **Admin → Cycle times**, and read Plant A's grid.
3. Look down the **PN-1003 (Line 1 Subassembly A)** column at the two line rows.

## Expected

R-317: "Cells with no number contribute nothing rather than a zero (unmeasured
work is unknown, not free) **and the row reports how many contributed**."

The `contributors` and `total` counts exist for exactly this. The panel's own
source says why, in the comment above `CycleGridCell`: "A total over 3 of 5
measured cells is not wrong, but it is not the line's full labour content
either, and a reader who cannot tell the two apart will plan against the smaller
number." And R-319 applies the same reasoning to the row that declines to add
up: it says "not added" in words "because a bare dash here would read as
'nothing entered'."

## Actual

Both line rows render the same glyph:

| Row     | PN-1003 shows | What is actually true                              |
| ------- | ------------- | -------------------------------------------------- |
| Line 1  | `—`           | the part IS made at Cell 1 and Cell 2; 0 of 2 timed |
| Line 2  | `—`           | the part is made nowhere under Line 2               |

The same pair appears in the PN-1004 column: Line 3 reads `—` while Cell 5 and
Cell 6 beneath it are editable boxes for that part.

The `0/2` the requirement asks for is not shown. `CycleTimesPanel.tsx:336-348`
renders the `contributors`/`total` annotation only inside the branch where
`contributors > 0`:

```tsx
{cell.contributors === 0 ? (
  <span className={styles.dash}>—</span>
) : (
  <>
    {formatCycle(cell.seconds)}
    {cell.contributors < cell.total && (
      <span className={styles.sumNote}> {cell.contributors}/{cell.total}</span>
    )}
  </>
)}
```

so the row that has the most to report — none of them measured — reports
nothing, and the row that reports `3/5` is the only one that says anything at
all. The `na` cell above it (`:297-303`) draws the identical dash. Only a hover
title separates them, and the `na` cell has no title at all — it carries
`aria-label="not made here"`, which the sum cell does not, so the two are not
distinguishable to a screen reader in the other direction either.

The effect on the screen is that a supervisor scanning the line rows for work
that still needs timing sees nothing to do. The per-plant counter ("6 of 22
places measured") is the only signal that any exists, and it does not say where.

## Lead

A suspicion, not a fact. This is presentation only — `buildCycleGrid` computes
`contributors` and `total` correctly, and `cycleTimes.test.ts` case G3 pins that
it does. The green case is about the MODEL; the clause it is verifying is about
the ROW, and there is no test of `CycleTimesPanel` at all (every other panel has
one: `settingsPanel`, `productsPanel`, `shiftsPanel`, `operatorsPanel`,
`trainingsPanel`, `importPanel`). So this is a green case that cannot fail for
the thing it names, and it is why no pin is filed here — the reproduction is a
screen, and the case that would catch it is a render test the developer owns.

No fix is prescribed. The shape that suggests itself is the one R-319 already
chose for the row next to it: say it in words rather than in a glyph — "0 of 2"
where the sum is empty, so the three states (not made here / made here but not
timed / timed) read as three different things.
