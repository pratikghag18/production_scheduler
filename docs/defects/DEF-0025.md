## Reproduction

At tip `980d1d3`, with the `Load Plant` volume fixture applied (`scripts/load/fixture.sql`) to the
database the running stack points at:

```
npx playwright test e2e/loadSanity.spec.ts --project=chromium
```

Read `e2e/loadSanity.spec.ts`'s drag section (the `block` locator through `dragMs = Date.now() - t0`,
around lines 126-145):

```js
const block = page.getByLabel(/^Load Op \d+ on /).first();
if ((await block.count()) > 0) {
  const box = await block.boundingBox();
  if (box !== null) {
    await page.mouse.move(box.x + box.width / 2, box.y + box.height / 2);
    await page.mouse.down();
    await page.mouse.move(box.x + box.width / 2 + 60, box.y + box.height / 2, { steps: 8 });
    const t0 = Date.now();
    await page.mouse.up();
    await page.waitForTimeout(0);
    await expect(trackNamed("Cell 1-1-1")).toBeVisible({ timeout: 60_000 });
    dragMs = Date.now() - t0;
  }
}
```

Compare against `e2e/touch.spec.ts`'s T2, the only other drag test in this suite that does not open
a popover first: it presses `Escape` before releasing specifically so the release "writes nothing
and the run keeps its seeded time" (its own comment, line ~405). `loadSanity.spec.ts`'s drag has no
such step between `mouse.move` and `mouse.up`.

## Expected

R-364 (`stated_by: agent`, written against this defect): a measurement spec must leave the database
exactly as it found it beyond what it deliberately seeds and tears down. The file's own header
promises this in words: *"`fixture.sql` adds a plant called 'Load Plant' and 420 `LOAD-%` operators
and touches nothing else; `teardown.sql` removes exactly those."* A drag that commits is not covered
by that promise and `teardown.sql` never undoes it.

## Actual

Traced the commit path rather than guessed: `useDragGesture.ts`'s `endBlockDrag` calls
`commitBlockDrag`, which for an ordinary (non-resize, non-run) drag calls
`updateAssignmentFields.mutate({ assignmentId: a.id, edit }, { onError: ... })` directly on
pointerup/mouseup -- no confirmation, no dry-run. `loadSanity.spec.ts`'s `page.mouse.up()` is exactly
this release, with no `Escape` and no compensating drag back.

Confirmed live in this session's own harness run (`test-results/tester-run-2026-09-09-1911.md`):
the spec ran against the developer's real database (the `Load Plant` fixture was present, not
skipped) and reported

```
drag on the big board           66 ms from mouse-up to settled
```

with no error toast anywhere in the run -- "settled" here means the optimistic patch held, i.e. the
mutation succeeded. Every execution of this spec (this session's tester run included) therefore
moves one real `Load Op N` assignment one hour later in whichever database `hasRealBackend` points
at, permanently and cumulatively: the second run moves an assignment two hours from where the
fixture seeded it, and so on. `scripts/load/teardown.sql` only removes the plant and the 420
operators it added; it does not, and cannot, know which assignment a given run happened to drag or
put its time back.

## Lead

A suspicion, not a fact. The narrowest fix mirrors `touch.spec.ts` T2: press `Escape` before
`page.mouse.up()` so the release commits nothing, and measure `dragMs` from mouse-down to whenever
the aborted drag's UI settles instead of from a commit. If the measurement is meant to time a real
commit (not just the gesture), the alternative is to drag the block back by the same 60px delta
immediately afterward and assert it landed within tolerance of its start, so the fixture is provably
restored rather than merely believed to be. Either way, nothing here touches product code --- the
fix is entirely inside the spec.
