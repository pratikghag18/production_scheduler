## Reproduction

In the running app at `http://localhost:5174` (a dev server on the committed tip
`b32ead3`; `http://localhost:5173` does the same):

1. Sign in with the dev switcher as **Admin (company — all three plants)**.
2. On the Board, leave the plant picker on **Plant A**.
3. Drag across **Cell 1**'s lane to open the **New** popover.
4. Open the **Product** dropdown.
5. Choose **Housing B** and press **Create**.

## Expected

R-272: "The create popover offers only products that belong at the cell and are
active." Housing B is made at Plant B. Plant A's Cycle times grid agrees — its
columns are PN-1001, PN-1002, PN-1003, PN-1004 and PN-9001 (Common Fastener),
and no Plant B part appears — so the same question, asked on the admin screen,
gives the right answer. The board should offer the same five.

R-239: "A client control is never ... shown for something the server refuses."

## Actual

The dropdown offers twelve parts, eight of which belong to other plants
(read from the live control):

```
["Housing A","Bracket A","Line 1 Subassembly A","Housing B","Bracket B",
 "Line 1 Subassembly B","Area 2 Frame B","Housing C","Bracket C",
 "Line 1 Subassembly C","Area 2 Frame C","Common Fastener"]
```

Choosing Housing B and pressing Create is refused by the database. Nothing is
created. The response body, captured off the wire:

```
HTTP 409  v1/rpc/create_run
{"code":"PT409",
 "details":"{\"id\": \"b30f1677-e8b4-4465-bf3d-58caf2c9c4b0\", \"kind\": \"product\", \"error\": \"not_offered_here\", \"node_id\": \"ce0d946d-d104-4c2e-be48-869220e3bad4\"}",
 "hint":null,
 "message":"That product does not belong to this part of the structure."}
```

Note that "Area 2 Frame A" is correctly ABSENT from the list — it is a Plant A
part scoped to Area 2, and Cell 1 is in Area 1. So the scope test is running and
is right about the parts it can see; it is only wrong about the parts belonging
to a plant that is not on screen.

The pin `src/test/defects/DEF-0002.test.ts` is red on this build:

```
FAIL  src/test/defects/DEF-0002.test.ts > DEF-0002: the board's product picker is
      scoped to the plant it is showing > does NOT offer a part made only at another plant
```

## Lead

A suspicion, not a fact.

`BoardPage.tsx:290-304` builds the offered list with
`productsOfferedHere(active, path, index.nodeById)`. `index.nodeById` holds only
the selected root's subtree — `board_window` scopes it, and the file says so
itself twenty lines further down, in `operatorPool`'s comment:

> "`index.nodeById` IS exactly this plant's subtree ... An earlier version
> resolved owner PATHS through `nodeById` and 'failed open' on an owner it could
> not find — but a different plant's owner is never in the scoped map, so every
> out-of-plant operator was kept: the bug this replaces."

`productOfferedAt` (`scope.ts`) fails open per place for the same reason the old
operator code did — `if (place === undefined) return true`. A Plant B part's
place is a Plant B node, which is never in a Plant A board's map, so the
fail-open fires on every one of them. R-310 fixed exactly this for operators in
session 32 by switching to membership (`ownedInScope`); the product half was
left on the path compare.

The fail-open itself is not wrong where it was designed for — a scope node the
reader may not READ. What is wrong is asking it against a map that was narrowed
by a VIEW CHOICE rather than by permission. `scope.ts`'s own header warns about
this confusion in another context ("NOT TO BE CONFUSED WITH THE PLANT FILTER
(§19.79) ... That is a VIEW CHOICE the reader made and can undo; this was a
PERMISSION"). The developer decides, but the shape that suggests itself is the
one `operatorPool` already uses: resolve places against membership in
`index.nodeById`, and treat a place outside the scoped set as a real "not this
plant" rather than an "I cannot tell".

Note the two halves of the design that this breaks. `CreatePopover.tsx:41-47`
records the decision that a product outside its scope is filtered OUT precisely
because "offering the product would offer a guaranteed refusal" — which is now
what happens. And the refusal it leans on does not arrive either; see DEF-0003.
